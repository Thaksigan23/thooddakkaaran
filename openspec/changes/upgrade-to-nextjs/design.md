## Context

The current site is a Vite 8 + React 19 single-page app: one `index.html`, one `src/main.jsx` that mounts `<App />` (inside `<I18nextProvider>` and `<StrictMode>`), 25 components in `src/components/`, one Vercel serverless function at `api/instagram.js`, Tailwind 3.4 styling, and a small custom Vite plugin that does two production-only jobs — replacing `__SITE_URL__` / `__INSTAGRAM_URL__` placeholders in `index.html` and writing `robots.txt` + `sitemap.xml` into `dist/` at `closeBundle`.

The site is content-heavy (~12 sections), strongly SEO-focused (full OG/Twitter tags, JSON-LD `Organization`), and deployed to Vercel. The Instagram feed is fetched from the browser against the Vercel function, which is cached at the edge for 30 minutes.

The migration target is **Next.js 15 with the App Router**, deployed on Vercel with no hosting change. We deliberately scope this change to a framework swap — not a TypeScript port, not a Tailwind v4 upgrade, not a redesign.

## Goals / Non-Goals

**Goals**

- Server-rendered HTML for `/` so crawlers and slow networks see real markup and metadata immediately.
- Real per-route metadata via Next.js Metadata API, replacing the build-time placeholder substitution in `index.html`.
- Convention-based `robots.txt` and `sitemap.xml` generated by Next.js, removing the custom Vite plugin's `closeBundle` step.
- Single runtime (Next.js Route Handlers) for the Instagram API, deleting the standalone `api/` Vercel function while keeping its public contract identical.
- Zero behavioral regressions for end users: same sections, same styling, same translations, same animations, same E2E smoke expectations.
- Smaller, faster LCP for hero imagery and self-hosted fonts.

**Non-Goals**

- TypeScript migration (separate change).
- Tailwind v4 / design tokens overhaul.
- New retail / e-commerce surface (the proposal mentions `NEXT_PUBLIC_ECOMMERCE_STORE_URL` only as a renamed env var).
- Per-route splitting of the marketing page into `/about`, `/contact`, etc. (it remains one scrollable page).
- Replacing i18next, Framer Motion, AOS, or any other runtime library.
- Changing the Instagram fetch model (client still fetches the route handler so the skeleton UX is preserved).

## Decisions

### Next.js 15 with App Router (not Pages Router)

- **Choice**: App Router (`app/`) with React Server Components and the Metadata API.
- **Why**: It is the current Next.js default, has first-class metadata + `robots`/`sitemap` conventions, and aligns with React 19 server-component semantics. Pages Router would force `_document.js` boilerplate for metadata and would not match React 19 patterns.
- **Cost**: Every interactive component (25 of 25 in `src/components/`) needs `"use client"`. This is mechanical and contained.

### Stay on JavaScript / `.jsx`

- **Choice**: No TypeScript in this change.
- **Why**: The codebase is 100% JS today; adding TS in the same PR doubles diff size and risk. The `eslint-config-next` we add still works for JS.
- **Cost**: We forgo type-checked `metadata` exports and Route Handler signatures. A follow-up `migrate-to-typescript` change can address this.

### Rendering: SSG for `/`, edge-cached Route Handler for `/api/instagram`

- **Choice**: `/` is statically prerendered. `/api/instagram/route.js` runs at request time but is cached via `Cache-Control: public, s-maxage=1800, stale-while-revalidate=3600` (identical to today's function).
- **Why**: The home page has no per-request server state — it reads only build-time env vars. Edge caching the Instagram response preserves today's behavior; using `export const revalidate = 1800` would also work but would couple the build to a specific revalidation strategy and be slightly harder to override per-request.
- **Alternative considered**: `export const revalidate = 1800` on the handler. Rejected because explicit `Cache-Control` matches today's response headers byte-for-byte, which makes Playwright + curl checks identical pre/post migration.

### Single-page layout under `app/`

- **Choice**: Exactly two new files in `app/` — `app/layout.jsx` (server component: `<html>`, `<head>`, metadata, JSON-LD, fonts, providers) and `app/page.jsx` (the home page, importing the existing 25 components). All other components remain in `src/components/` and are imported into `app/page.jsx` from there.
- **Why**: Minimises diff and keeps the existing component directory intact. Section order is preserved exactly.

### Client/server boundary

- **Choice**: `app/layout.jsx` and `app/page.jsx` are server components. A small `src/components/providers/AppProviders.jsx` client component wraps everything inside `app/layout.jsx`'s `<body>` and provides `I18nextProvider`, AOS initialisation, and any other browser-only setup. Every component currently using hooks, Framer Motion, AOS, or `window`/`document`/`localStorage`/`navigator` gets `"use client"` at the top.
- **Why**: This isolates client-only concerns to one provider boundary while letting Next.js statically prerender the page HTML around it. A grep against the current `src/components/` shows the following need `"use client"`: `Navbar`, `Hero`, `About`, `Services`, `Products`, `WhyChooseUs`, `Stats`, `VisionMission`, `Gallery`, `Testimonials`, `Instagram`, `Contact`, `Footer`, `Loader`, `ScrollProgress`, `Whatsapp`, `BackToTop`, `Map`, `ErrorBoundary`, `CookieConsent`, `DocumentLangSync`, `Reveal`, `GrowSectionImage`, `ThemeToggle`, `LanguageSwitcher` — i.e. all of them, because they use either `useState`/`useEffect` or `motion`.

### Env var rename (`VITE_*` → `NEXT_PUBLIC_*`)

- **Choice**: Mechanical rename of all browser-exposed env keys; server-only keys (`INSTAGRAM_ACCESS_TOKEN`, `INSTAGRAM_BUSINESS_ACCOUNT_ID`, `ALLOWED_CORS_ORIGINS`) keep their names.
- **Why**: Next.js only exposes `NEXT_PUBLIC_*` to the client bundle; any other key remains server-only by default.
- **Affected files** (grepped): `src/constants/site.js`, `src/constants/social.js`, `src/constants/contact.js`, `src/components/Contact.jsx`, `src/components/Map.jsx`, `src/components/CookieConsent.jsx`, plus `.env.example` and Vercel project settings.

### Replace `index.html` injection with Metadata API + JSON-LD script

- **Choice**: `app/layout.jsx` exports `metadata` for `<title>`, `description`, `keywords`, `authors`, `themeColor`, `viewport`, `robots`, `alternates.canonical`, `openGraph`, `twitter`, and `icons.icon`. The Organization JSON-LD is emitted via an inline `<script type="application/ld+json" dangerouslySetInnerHTML={...} />` inside the layout's `<head>` because Next.js does not have a dedicated structured-data field.
- **Why**: The Metadata API is the idiomatic replacement and removes string-template placeholder substitution entirely. `dangerouslySetInnerHTML` for JSON-LD is the documented Next.js pattern.

### Replace plugin file emission with `app/robots.js` + `app/sitemap.js`

- **Choice**: Both files are tiny modules that read `process.env.NEXT_PUBLIC_SITE_URL` and return the structured object Next.js expects.
- **Why**: First-class Next.js convention, no extra dependency, automatically served at `/robots.txt` and `/sitemap.xml`.

### Instagram API: move and preserve

- **Choice**: Move `api/instagram.js` to `app/api/instagram/route.js`. Adapt the existing handler shape (`(req, res) =>` Node) to the Web standard signature Next.js Route Handlers use (`async function GET(request)` returning `Response` / `NextResponse`). Keep response payload, status codes, Graph API URL, `limit=9`, post normalisation (VIDEO → `thumbnail_url`), CORS allow-list, `OPTIONS` handling, and `Cache-Control` byte-identical.
- **Why**: Minimum-risk port. The spec captures the contract; the handler implementation is just a translation between Node res object and Web `Response`.

### Fonts and images

- **Choice**: Replace the Google Fonts `<link>` for Poppins with `next/font/google`. Use `next/image` for `Hero` background/logo and the `Loader` logo only; keep `<img>` for the Gallery, Instagram grid, and decorative images for now (they already use `loading="lazy"` and `decoding="async"`).
- **Why**: `next/font` self-hosts fonts (no FOIT, no third-party request, no CLS). `next/image` gives us width/height + lazy + AVIF/WebP for the LCP element. A full image sweep is out of scope.

### Security headers stay in `vercel.json` for now

- **Choice**: Leave the existing `vercel.json` headers in place rather than moving them to `next.config.js` `headers()`.
- **Why**: `vercel.json` headers are applied at the Vercel edge before any Next.js compute runs, which is strictly faster and cheaper. Moving them later (e.g., to gain header logic per-route) is trivial.

### ESLint and tooling swap

- **Choice**: Replace `eslint-plugin-react-refresh` (Vite-only) with `eslint-config-next`. Keep `@eslint/js`, `eslint-plugin-react-hooks`, flat config.
- **Why**: `eslint-config-next` integrates Next-specific rules (`@next/next/no-html-link-for-pages`, image rules, etc.) and is the documented setup.

### Playwright

- **Choice**: Update `playwright.config.js` `webServer.command` to `npm run start -- -p 4173` (or change `baseURL` to `:3000`) and keep tests as-is.
- **Why**: Tests already match landmark and title selectors that survive the migration. We avoid changing the test surface in this change.

## Risks / Trade-offs

- **[Risk] Env var cutover causes a runtime gap on Vercel.** The deploy that ships Next.js will look for `NEXT_PUBLIC_*` but only `VITE_*` exists in the project's environment.
  → **Mitigation**: Add the new `NEXT_PUBLIC_*` keys in the Vercel UI _before_ promoting the deploy; verify on a preview deployment first. Keep old `VITE_*` keys in place until rollout is confirmed.

- **[Risk] Hydration mismatches from components that read `window` synchronously.** Several existing components (`Navbar`, `BackToTop`, `ScrollProgress`, `ThemeToggle`, `CookieConsent`) touch `window` on render.
  → **Mitigation**: All of them already wrap browser access in `useEffect`. Audit each component during port; gate any remaining synchronous access behind `typeof window !== "undefined"` or move into `useEffect`. Run `next dev` and watch the console for hydration warnings.

- **[Risk] `DocumentLangSync` mutates `<html lang>` after mount, causing a flash.** Today this is invisible because the entire SPA is client-rendered; with SSR the server-rendered `lang="en"` is replaced by the user's selected language post-hydration.
  → **Mitigation**: Acceptable for v1 — language switching already happens client-side. If the flash is noticeable, follow-up change can read a `NEXT_LOCALE` cookie in the layout and pass it as the initial `lang`.

- **[Risk] `next/image` with `Hero`/`Loader` could break existing layout if `width`/`height` are wrong.**
  → **Mitigation**: Convert one image at a time, verify visually, fall back to plain `<img>` if layout shifts. The spec only requires `next/font`; `next/image` is a quality improvement, not a hard requirement.

- **[Risk] Tailwind purge strips classes if `content` glob misses `app/`.**
  → **Mitigation**: Add `./app/**/*.{js,jsx}` to `tailwind.config.js content` array as part of the same commit that introduces `app/`.

- **[Risk] AOS initialised at the wrong moment (it currently runs in `main.jsx` after `createRoot`).**
  → **Mitigation**: Move `AOS.init(...)` into `AppProviders` inside `useEffect`, so it runs once after hydration just like today.

- **[Risk] Vercel auto-detection picks up both `vite.config.js` (removed) and `next.config.js` and gets confused if both are present in some commit.**
  → **Mitigation**: Delete `vite.config.js` and `index.html` in the same commit that adds `next.config.js`. Verify "Framework Preset" in the Vercel project is set to "Other" (auto-detect) or explicitly "Next.js".

- **[Trade-off] Bigger node_modules and longer cold builds.** Next.js + its compiler ship more than Vite + plugin-react.
  → **Mitigation**: Acceptable — we trade some build time for SSR, image opt, and metadata.

- **[Trade-off] React Server Components require discipline.** We start by making just `app/layout.jsx` + `app/page.jsx` server components. If a contributor later imports a client-only library from `app/page.jsx`, the build will fail.
  → **Mitigation**: Document the pattern in `README.md`; the boundary is clearly defined by `AppProviders`.

## Migration Plan

1. **Branch and scaffold.** Create `chore/upgrade-to-nextjs`. Add `next`, `eslint-config-next`; remove `vite`, `@vitejs/plugin-react`, `eslint-plugin-react-refresh`. Add `next.config.js`, `app/layout.jsx`, `app/page.jsx`, `app/robots.js`, `app/sitemap.js`, and `app/api/instagram/route.js`. Keep `index.html` and `vite.config.js` initially so the diff reviewer can compare side-by-side; delete them at the end of the same PR.
2. **Port providers and components.** Create `src/components/providers/AppProviders.jsx` (client). Add `"use client"` to all 25 components in `src/components/`. Rename every `import.meta.env.VITE_*` to `process.env.NEXT_PUBLIC_*`.
3. **Replace HTML head and asset emission.** Implement the Metadata API in `app/layout.jsx`. Implement `app/robots.js` and `app/sitemap.js`. Delete the `inject-site-meta` Vite plugin definition.
4. **Move the API.** Translate `api/instagram.js` to `app/api/instagram/route.js`, preserving status codes, JSON shape, CORS, and `Cache-Control`. Delete the old file.
5. **Update tooling.** Rewrite `package.json` scripts (`dev`, `build`, `start`, `lint`). Update `tailwind.config.js` `content`. Update `eslint.config.js` to use `eslint-config-next`. Update `playwright.config.js` `webServer` + `baseURL`. Update `.gitignore` (add `.next/`, remove `dist/`). Update `.env.example` and `README.md`.
6. **Local verification.** `npm run dev` → no console errors, sections render, language switcher works. `npm run build && npm start` → SSG home page returns full HTML; `/robots.txt`, `/sitemap.xml`, `/api/instagram` respond correctly. `npm run lint` clean. `npm run test:e2e` passes against the started Next server.
7. **Vercel env rekey.** In the Vercel project settings, add every `NEXT_PUBLIC_*` key with the same value as its `VITE_*` counterpart. Do this on Production and Preview scopes.
8. **Preview deploy and smoke.** Push the branch; review the Vercel preview. Run `curl -I` for security headers, fetch `/robots.txt`, `/sitemap.xml`, `/api/instagram`, and verify OG tags via `view-source:`.
9. **Promote.** Merge to `main`. Vercel deploys. Re-crawl in Google Search Console.

**Rollback**

- Revert the merge commit. Vercel redeploys the previous Vite build. The old `VITE_*` env vars are still in the Vercel project (we did not delete them), so the previous deploy boots cleanly.
- Once the Next.js deploy has been stable for a week, delete the obsolete `VITE_*` keys in Vercel as a follow-up housekeeping commit (no code change required).

## Open Questions

- **Adopt `next/image` for the Gallery and Instagram grids in this change, or follow up?** Recommendation: follow up. The hero + loader cover the LCP win; gallery/Instagram are below-fold and already lazy.
- **Move security headers to `next.config.js`?** Recommendation: not in this change — see decision above.
- **Add a `NEXT_LOCALE` cookie so the SSR `<html lang>` matches the user's selection on first paint?** Recommendation: defer; quantify the flash first.
- **Should the Instagram handler use `export const runtime = "edge"`?** Recommendation: defer. Node runtime keeps behaviour identical to the current Vercel function; edge can be evaluated once we measure cold-start impact.
